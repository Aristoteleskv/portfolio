## What it is

An institutional website for a consulting and training company, with public
pages, an application area and a panel where the team edits text, imagery,
vacancies, partners and articles — without touching code or deploying.

The real goal was not "make a nice-looking site". It was **to get the client
off WordPress**: every time a headline changed, someone had to ask a
developer. With a translations table and a panel, the team writes.

## The decision that organises everything: one process

Angular 17 generates an SSR server, and that server is an Express app. Instead
of deploying the frontend to one machine and the API to another, **both are
the same process** and answer on the same port.

```ts title="server.ts"
server.use('/api/careers', careerRoutes);
server.use('/api/admin', adminRoutes);
// Everything else is the Angular SSR engine.
server.get('*', (req, res, next) => {
  commonEngine
    .render({ bootstrap, documentFilePath: indexHtml, url, publicPath: browserDistFolder })
    .then((html) => res.send(html))
    .catch((err) => next(err));
});
```

The practical consequence: no CORS between page and API, no two deploys to
coordinate, and the API lives on the same domain — which lets the SPA and the
SSR share cookies with no extra work.

## Content the team can edit

The SQLite database has 15 tables, and the core of the project sits in them:
each section of the site reads from a table, and each table has a screen in
the panel.

| Table | What it controls |
| --- | --- |
| `translations` | All visible copy, per language |
| `carousel_slides` | Home carousel slides |
| `partners` / `certifications` | Partner and certification logos |
| `jobs` + `applications` | Vacancies and applications (with CV upload) |
| `knowledge_articles` | Knowledge base articles, by category |
| `idea_submissions` + `teams` | Idea submission and team formation |
| `users` + `user_profiles` | Panel accounts and profiles |

The translations are the sensitive part: `translations` has
`UNIQUE(section, key)`, which guarantees there are never two entries for the
same key. The rest of the schema is predictable; the difference is that there
is no copy inside the code.

```ts title="backend/db.ts"
// The seed only runs if the table is empty — it never overwrites what
// someone has already edited through the panel.
const userCount = db.prepare('SELECT COUNT(*) as cnt FROM users').get();
if (userCount.cnt === 0) { /* insert the defaults */ }
```

## Seven languages, one route table

The routes are generated by a function, not hand-written seven times. `pt`,
`en`, `fr`, `ru`, `zh`, `es` and `ln` all come out of the same array, each with
the same pages and the same *lazy-loaded* components.

```ts title="src/app/app.routes.ts"
const supportedLanguages = ['pt', 'en', 'fr', 'ru', 'zh', 'es', 'ln'];

supportedLanguages.forEach((lang) => {
  languageRoutes.push({
    path: lang,
    children: [
      { path: '', component: HomeComponent },
      { path: 'sobre', loadComponent: () => import('./pages/sobre/sobre.component').then((m) => m.SobreComponent) },
      // ... the rest of the pages, all lazy
    ],
  });
});
```

Every page is a `loadComponent`, which means the initial bundle does not carry
the screens the visitor never opened. With SSR, the first HTML already arrives
with content — not an empty page waiting for JavaScript.

## Where SSR complicates things

`TranslationService` is the most honest example. The same service has to read
translations two ways: `fetch` in the browser, `fs.readFileSync` on the server.

```ts title="src/app/core/translation.service.ts"
if (isPlatformServer(this.platformId)) {
  // On the server the file is on disk; in the browser it goes over HTTP.
  const filePath = path.join(process.cwd(), 'src', 'assets', 'i18n', `${lang}.json`);
  this.translations = JSON.parse(fs.readFileSync(filePath, 'utf8'));
} else {
  const response = await fetch(`assets/i18n/${lang}.json`);
  this.translations = await response.json();
}
```

It is a real fork, not an elegant abstraction — and it is the price of having
SSR with file-based translations. `AdminGuard` has the same constraint: it
returns `false` on the server, because a protected route has nothing to render
before the token exists.

## Performance, measured in code

There is a `PerformanceService` that does not simply claim the site is fast:
it collects LCP, FCL, FID, CLS and TTI, and correlates them with navigation.
It is the service an institutional client needs most, because nobody is going
to ask them for a Lighthouse report — quality is what they sell.

```ts title="src/app/core/performance.service.ts"
private initPerformanceMonitoring(): void {
  // Core Web Vitals
  this.measureCoreWebVitals();
  this.setupRoutePerformanceTracking(); // NavigationEnd -> time per route
}
```

`LazyLoadService` uses `IntersectionObserver` to defer loading whatever is off
screen, and `OptimizationService` detects what the browser supports before
using it.

## Authentication

JWT with `bcrypt` for the password, and two levels: `authMiddleware` validates
the token, `requireRole('admin')` validates the role. On the frontend there is
a `CanActivate` that always returns a `UrlTree` — someone authenticated but
not an admin gets sent to the dashboard instead of an empty screen.

## What I would do differently

This is the project I have the most to say about, because it is the one that
grew the most:

- **The JWT secret has a fallback in the code.**
  `process.env['JWT_SECRET'] || 'grupo-paralela-secret-key-change-in-production'`
  works in development and is a problem in production. A fallback secret
  should never exist: if the variable is not set, the process should not boot.
- **Same for the default password.** The seed creates
  `admin@grupoparalela.com` / `admin123`. A first run should ask for the
  password, not generate one.
- **`styles.scss` is 29,773 lines.** Most of it is third-party CSS pasted in.
  It could import only what is used and get back to a few hundred lines.
- **Legacy JavaScript living next to Angular.** `barba.js`, `fancybox` and a
  CDN-served GSAP 3.2.4 sit in `assets/js/` beside modern code. Either they
  become components, or they go.
- **The README says five languages; the routes have seven.** `es` and `ln` are
  undocumented, and Lingala is the most interesting decision of the lot — it
  deserves to be written down somewhere.
- **No behaviour tests.** There are 12 spec files, but they are structural:
  what the CLI generated. What should be tested is `AdminGuard` and
  `TranslationService` in server mode.
